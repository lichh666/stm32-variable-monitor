# 最终版本说明

## 1. 项目名称

基于 STM32F103ZE 的运行时变量监控与在线调参系统

## 2. 最终演示版本

本项目最终上板演示采用 no-LCD 瘦身版本，工程文件为：

```text
02_固件代码/RuntimeMonitor/Projects/MDK-ARM/atk_f103_nolcd.uvprojx
```

打开方式：

1. 使用 Keil uVision5 打开 `atk_f103_nolcd.uvprojx`；
2. 执行 `Rebuild all target files`；
3. 编译通过后使用 ST-Link / JTAG 下载到正点原子战舰 STM32F103ZE 开发板；
4. 使用 XCOM V2.8 通过 CH340 USB 串口进行测试。

## 3. 最终演示硬件与软件环境

| 项目     | 内容                       |
| ------ | ------------------------ |
| 开发板    | 正点原子战舰 STM32F103ZE       |
| MCU    | STM32F103ZE              |
| 固件工程   | `atk_f103_nolcd.uvprojx` |
| 编译环境   | Keil uVision5            |
| 下载方式   | ST-Link / JTAG           |
| PC 端工具 | XCOM V2.8                |
| 串口连接   | CH340 USB 串口             |
| 串口参数   | 115200, 8N1, None        |
| 协议格式   | ASCII 文本命令，命令以回车换行结束     |

## 4. 最终实现功能

最终演示版本实现了以下功能：

1. PC 端通过 XCOM 与 STM32 建立 USART 串口通信；
2. 支持 `PING` 命令进行连通性测试；
3. 支持 `LIST` 命令枚举 STM32 内部变量表；
4. 支持 `GET <name>` 命令读取运行时变量；
5. 支持 `SET <name> <value>` 命令在线修改可写变量；
6. 支持通过 `SET alarm_limit 280` 修改报警阈值；
7. 支持通过 `GET alarm` 查看报警状态；
8. 支持 LED 和蜂鸣器对报警状态进行板端反馈；
9. 支持通过 `SET beep_en 0` 在线关闭蜂鸣器；
10. KEY 驱动已接入，可作为本地调参或扩展输入。

## 5. 最终测试命令

最终演示视频按照以下命令顺序进行：

```text
PING
LIST
GET temp_x10
SET alarm_limit 280
GET alarm
SET beep_en 0
```

对应测试含义如下：

| 命令                    | 测试目的                   |
| --------------------- | ---------------------- |
| `PING`                | 验证 PC 与 STM32 串口通信是否正常 |
| `LIST`                | 验证 STM32 能否返回变量表       |
| `GET temp_x10`        | 读取当前模拟温度               |
| `SET alarm_limit 280` | 将报警阈值在线修改为 28.0℃       |
| `GET alarm`           | 查看报警状态是否被触发            |
| `SET beep_en 0`       | 在线关闭蜂鸣器使能              |

## 6. no-LCD 版本说明

项目开发过程中曾尝试加入 LCD 显示模块，用于显示温度、阈值和报警状态。但加入 LCD、FSMC/SRAM 等相关驱动后，工程体积超过 Keil 非商业版本代码大小限制，出现链接错误。

为保证最终演示稳定、可复现，最终采用 no-LCD 瘦身版本：

```text
atk_f103_nolcd.uvprojx
```

该版本保留了本项目的核心功能：

* USART 在线变量监控；
* `PING` / `LIST` / `GET` / `SET` 协议命令；
* LED 报警反馈；
* 蜂鸣器报警反馈；
* KEY 驱动接入；
* PC 端在线关闭蜂鸣器。

LCD 接口在软件结构中作为预留接口说明，但最终演示版本未启用 LCD 显示。

## 7. PC 端工具说明

本项目最终使用 XCOM V2.8 作为 PC 端简易串口调试界面。

选择 XCOM 的原因是：

1. 使用成本低，不需要额外开发复杂图形界面；
2. 能够直接发送 ASCII 文本命令；
3. 能清楚显示 STM32 返回的 `OK`、`DATA`、`VAR` 等响应；
4. 符合题目中“采用简易方式复现主机接口软件核心功能”的要求。

本项目未将 Python 上位机作为最终演示工具。

## 8. 最终版本与题目要求的对应关系

| 题目要求                | 本项目实现方式                                       |
| ------------------- | --------------------------------------------- |
| PC 端能查看 STM32 运行时变量 | 通过 `LIST` 和 `GET <name>` 命令实现                 |
| PC 端能修改 STM32 变量    | 通过 `SET <name> <value>` 命令实现                  |
| STM32 与 PC 通信       | 使用 CH340 USB 串口与 USART1                       |
| 低成本适配已有 STM32 程序    | 通过 `Protocol`、`AppMonitor`、`BoardPort` 分层结构实现 |
| 有实际运行结果             | XCOM 截图、Keil 编译截图、演示视频                        |
| 有板端反馈               | LED 和蜂鸣器报警反馈                                  |

## 9. 最终结论

最终 no-LCD 演示版本已经完成题目 12 的核心目标：不使用仿真器查看内存变量，而是通过 USART 串口和 PC 端简易界面，在 STM32 程序运行过程中读取变量、修改参数，并通过 LED 与蜂鸣器验证参数修改对系统运行状态的实时影响。
