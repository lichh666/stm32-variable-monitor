# README_固件移植说明

本文件说明《基于 STM32F103ZE 的运行时变量监控与在线调参系统》最终固件工程的来源、结构、移植方法和复现实验步骤。

## 1. 最终固件版本

本项目最终上板演示使用 no-LCD 瘦身版本工程：

```text
RuntimeMonitor/Projects/MDK-ARM/atk_f103_nolcd.uvprojx
```

该工程基于正点原子战舰 STM32F103ZE HAL 库串口实验工程移植而来，保留 USART 串口通信、运行时变量表、`PING/LIST/GET/SET/HELP` 命令、LED 报警、蜂鸣器报警和 KEY 驱动接入等核心功能。

最终演示未启用 LCD 显示模块。LCD 接口在软件结构中保留为预留接口，但由于 Keil 非商业版本代码大小限制，最终上板演示采用 no-LCD 版本。

## 2. 工程目录结构

最终固件工程主要目录如下：

```text
RuntimeMonitor/
├── AppMonitor/
├── BoardPort/
├── Drivers/
├── Middlewares/
├── Projects/
│   └── MDK-ARM/
│       └── atk_f103_nolcd.uvprojx
├── Protocol/
└── User/
```

各目录作用如下：

| 目录                 | 作用                                       |
| ------------------ | ---------------------------------------- |
| `Protocol`         | 串口协议层，负责 `PING`、`LIST`、`GET`、`SET`、`HELP` 等命令解析 |
| `AppMonitor`       | 应用监控层，负责变量表、模拟温度、虚拟 ADC、报警逻辑和周期任务      |
| `BoardPort`        | 板级适配层，负责串口发送、LED、BEEP、KEY 等外设适配          |
| `User`             | 主程序入口、系统中断文件等用户代码                        |
| `Drivers`          | STM32 HAL 库、系统驱动、BSP 外设驱动                |
| `Middlewares`      | 原始工程中间件目录，保留以保证工程完整性                     |
| `Projects/MDK-ARM` | Keil 工程目录，最终打开 `atk_f103_nolcd.uvprojx`  |

## 3. 移植思路

本项目的目标是用低成本方式复现 STM32CubeMonitor 的核心思想：在 STM32 程序运行过程中，PC 端通过通信接口查看和修改目标程序中的变量。

为便于移植到已有 STM32 工程，固件采用分层结构：

```text
PC 端 XCOM
    ↓
CH340 USB 串口 / USART1
    ↓
Protocol 协议层
    ↓
AppMonitor 应用监控层
    ↓
BoardPort 板级适配层
    ↓
LED / BEEP / KEY 等板端外设
```

其中：

* `Protocol` 不直接依赖具体开发板，只负责协议命令解析；
* `AppMonitor` 维护变量表和报警逻辑；
* `BoardPort` 封装具体板子的串口、LED、蜂鸣器和按键操作；
* 移植到其他 STM32 工程时，主要修改 `BoardPort` 即可适配不同外设。

## 4. 主要变量

当前版本在 `AppMonitor/app_monitor.c` 中注册的变量包括：

| 变量名           | 含义     | 说明         |
| ------------- | ------ | ---------- |
| `tick_s`      | 系统运行秒数 | 只读         |
| `temp_x10`    | 模拟温度   | 单位 0.1℃    |
| `alarm_limit` | 报警阈值   | 单位 0.1℃，可写 |
| `adc_mv`      | 虚拟 ADC 电压 | 单位 mV，可写 |
| `led_period`  | LED0 翻转周期 | 单位 100ms，可写 |
| `alarm`       | 报警状态   | bool，只读    |
| `beep_en`     | 蜂鸣器使能  | bool，可写    |
| `key_count`   | 按键计数   | 只读         |
| `run`         | 系统运行使能 | bool，可写    |

说明如下：

* `temp_x10` 为演示用的虚拟过程量，代码中按三角波方式缓慢变化；
* `adc_mv` 为随 `temp_x10` 联动计算出的虚拟 ADC 电压；
* `led_period` 用于控制 LED0 心跳闪烁周期；
* `run=0` 时，`AppMonitor_Tick100ms()` 中的周期更新逻辑会暂停；
* 最终演示中重点展示的可写变量仍然是 `alarm_limit` 和 `beep_en`。

## 5. 板级外设映射

最终 no-LCD 演示版本中，板端外设映射如下：

| 外设        | 引脚             | 说明                |
| --------- | -------------- | ----------------- |
| USART1_TX | PA9            | STM32 向 PC 返回数据   |
| USART1_RX | PA10           | PC 向 STM32 发送命令   |
| LED0      | PB5            | 心跳 / 自检指示，低电平点亮   |
| LED1      | PE5            | 报警指示，低电平点亮        |
| BEEP      | PB8            | 报警蜂鸣器，高电平响        |
| KEY       | 以 `key.h` 定义为准 | 驱动已接入，可作为本地按键输入扩展 |

## 6. 关键代码接入点

### 6.1 主程序入口

在 `main.c` 中完成 HAL、时钟、串口、LED 等初始化后，调用：

```c
AppMonitor_Init();

while (1)
{
    AppMonitor_Loop();
}
```

当前代码中的 `AppMonitor_Loop()` 采用简单演示方式：每次循环执行一次 `AppMonitor_Tick100ms()`、一次 `Monitor_Periodic100ms()`，随后 `Board_DelayMs(100)` 延时 100ms。  
也就是说，本工程当前版本并未使用独立定时器中断驱动 100ms 周期任务，而是直接在主循环中完成周期调度。

### 6.2 串口接收回调

在 USART 接收回调中，将收到的字符送入协议处理函数：

```c
AppMonitor_OnUartChar((char)g_rx_buffer[0]);
```

当前工程中该调用位于 `Drivers/SYSTEM/usart/usart.c` 的 `HAL_UART_RxCpltCallback()` 中。  
协议层会逐字符缓存输入，直到收到回车换行后再解析完整命令。

### 6.3 板级适配函数

`BoardPort` 提供如下适配接口：

```c
Board_UartPuts();
Board_DelayMs();
Board_LedSet();
Board_BeepSet();
Board_KeyScan();
```

此外还保留了：

```c
Board_Init();
Board_LcdShowStatus();
```

其中 `Board_LcdShowStatus()` 在当前 no-LCD 版本中为空实现，仅作为后续扩展 LCD 显示的预留接口。  
`Board_Init()` 会完成 GPIO 和按键初始化，并执行一次 LED0、LED1、BEEP 自检提示。

## 7. 编译与下载步骤

1. 打开 Keil uVision5；
2. 打开工程：

```text
RuntimeMonitor/Projects/MDK-ARM/atk_f103_nolcd.uvprojx
```

3. 执行：

```text
Project → Rebuild all target files
```

4. 编译结果应为：

```text
0 Error(s), 0 Warning(s)
```

5. 使用 ST-Link / JTAG 下载程序：

```text
Flash → Download
```

6. 下载成功后，打开 XCOM V2.8 进行串口测试。

## 8. 串口测试参数

XCOM 串口参数设置为：

```text
波特率：115200
数据位：8
停止位：1
校验位：None
发送格式：ASCII 文本
16进制发送：不勾选
16进制显示：不勾选
发送新行：勾选
```

COM 口以设备管理器中 CH340 对应端口为准，例如：

```text
COM3: USB-SERIAL CH340
```

## 9. 最终演示命令

最终演示视频按照以下顺序逐条发送命令：

```text
PING
LIST
GET temp_x10
SET alarm_limit 280
GET alarm
SET beep_en 0
```

实际协议层还支持：

```text
HELP
```

对应功能如下：

| 命令                    | 功能                 |
| --------------------- | ------------------ |
| `PING`                | 测试 PC 与 STM32 串口通信 |
| `LIST`                | 返回运行时变量表           |
| `GET temp_x10`        | 读取当前模拟温度           |
| `SET alarm_limit 280` | 将报警阈值在线修改为 28.0℃   |
| `GET alarm`           | 读取报警状态             |
| `SET beep_en 0`       | 在线关闭蜂鸣器            |
| `HELP`                | 返回支持的命令格式说明        |

## 10. LCD 说明

项目开发过程中曾尝试加入 LCD 显示模块，用于显示温度、阈值、报警状态等信息。但加入 LCD、FSMC/SRAM 等相关驱动后，工程体积超过 Keil 非商业版本代码大小限制，导致链接失败。

为保证最终演示稳定可复现，最终提交采用 no-LCD 瘦身版本：

```text
atk_f103_nolcd.uvprojx
```

LCD 显示接口在软件结构中作为预留接口保留，当前体现在 `Board_LcdShowStatus()` 函数上；但在 no-LCD 演示版本中，该函数为空实现，不参与实际显示。

## 11. 移植总结

本工程通过 `Protocol + AppMonitor + BoardPort` 的分层结构，将运行时变量监控逻辑与具体硬件平台解耦。若需要移植到其他 STM32 工程，主要步骤为：

1. 保留或移植 `Protocol` 和 `AppMonitor`；
2. 根据目标板修改 `BoardPort` 中的串口、LED、蜂鸣器、按键接口；
3. 在主循环中调用 `AppMonitor_Init()` 和 `AppMonitor_Loop()`；
4. 在串口接收中断或回调中调用 `AppMonitor_OnUartChar()`；
5. 通过 PC 串口工具发送 `PING`、`LIST`、`GET`、`SET`、`HELP` 命令进行测试。

最终结果表明，该工程能够在 STM32 程序持续运行的情况下，通过 PC 串口命令读取变量、修改参数，并将参数变化实时反映到 LED 和蜂鸣器等板端外设状态中。README 中描述的核心结构、移植方法和演示流程与当前代码实现保持一致。
