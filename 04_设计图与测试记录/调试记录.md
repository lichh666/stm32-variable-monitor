# 调试记录

本文件记录《基于 STM32F103ZE 的运行时变量监控与在线调参系统》从环境搭建、串口验证、协议移植到最终上板演示的主要调试过程。

## 1. 开发环境搭建

### 1.1 Keil 与芯片支持包安装

首先安装 Keil uVision5，并在 Pack Installer 中安装 STM32F1 系列相关支持包。工程目标芯片为 STM32F103ZE，对应正点原子战舰 STM32F103ZE 开发板。

初次打开正点原子 HAL 库例程时，Keil 工程默认使用 ARM Compiler 5，但当前环境中未安装 ARM Compiler 5，因此编译时出现编译器不可用的问题。后续将工程编译器切换为 ARM Compiler 6。

### 1.2 ARM Compiler 6 兼容处理

切换到 ARM Compiler 6 后，工程出现 LTO 相关错误：

```text
use of LTO is disallowed in this variant of Arm Compiler for Embedded
```

排查后确认是工程启用了 Link Time Optimization，而当前 Keil 版本不支持该优化选项。因此在 Keil 工程设置中关闭 LTO，随后原始串口实验工程可以正常编译通过。

## 2. 正点原子串口实验跑通

### 2.1 选择底板工程

从正点原子资料包中选择 HAL 库版本的“实验5 串口实验”作为底板工程。该工程已经包含 HAL 初始化、系统时钟、USART1 初始化、串口接收中断、LED 初始化等基础内容，适合作为本项目移植起点。

### 2.2 串口硬件连接

开发板通过 CH340 USB 串口连接 PC，PC 端使用 XCOM V2.8 串口调试助手。串口参数设置为：

```text
115200 bps
8 data bits
1 stop bit
None parity
ASCII 文本
发送新行：勾选
```

### 2.3 原始串口回显验证

下载原始串口实验程序后，XCOM 能够收到开发板输出的提示信息。向开发板发送 `hello` 后，开发板可以返回接收到的内容，说明 PC 到 STM32、STM32 到 PC 的双向串口通信均已正常。

该阶段验证了：

* Keil 工程可以编译；
* ST-Link 可以下载程序；
* CH340 串口可以被 PC 识别；
* USART1 串口收发链路正常。

## 3. 移植运行时变量监控框架

### 3.1 工程路径调整

在移植过程中，因工程路径中包含中文目录，ARM Compiler 6 在编译新增文件时出现路径乱码和找不到文件的问题。随后将工程复制到纯英文路径下：

```text
D:\STM32_Project\RuntimeMonitor
```

并重新添加新增 `.c` 文件和 Include Path，解决了路径兼容问题。

### 3.2 添加功能模块

在 Keil 工程中加入以下模块：

```text
Protocol/
  monitor_protocol.c
  monitor_protocol.h

AppMonitor/
  app_monitor.c
  app_monitor.h

BoardPort/
  board_port.c
  board_port.h
```

其中：

* `Protocol` 负责解析 `PING`、`LIST`、`GET`、`SET` 等串口命令；
* `AppMonitor` 负责变量表、模拟温度、报警逻辑和周期任务；
* `BoardPort` 负责把通用逻辑连接到具体开发板外设。

### 3.3 修改主程序

将原始串口回显实验中的主循环替换为：

```c
AppMonitor_Init();

while (1)
{
    AppMonitor_Loop();
}
```

原来的 `g_usart_rx_sta` 和 `g_usart_rx_buf` 回显逻辑不再作为主功能使用。

### 3.4 修改串口接收流程

在 `usart.c` 的串口接收完成回调中，将接收到的单字节传入协议处理函数：

```c
AppMonitor_OnUartChar((char)g_rx_buffer[0]);
```

随后重新启动下一次单字节接收。这样 PC 端每发送一个字符，STM32 都能送入协议层缓冲区，直到检测到回车换行后解析完整命令。

## 4. 串口协议功能调试

### 4.1 启动信息验证

下载移植后的程序后，按下开发板 RESET，XCOM 中出现：

```text
BOOT STM32_RUNTIME_MONITOR 1.0
HELP: LIST | GET <name> | SET <name> <value> | PING
```

说明程序已经进入运行时变量监控系统，且 `Board_UartPuts()` 串口输出正常。

### 4.2 PING 测试

发送：

```text
PING
```

返回：

```text
OK PONG
```

说明 PC 与 STM32 之间的命令链路正常。

### 4.3 LIST 测试

发送：

```text
LIST
```

开发板返回变量表，例如：

```text
VAR tick_s ...
VAR temp_x10 ...
VAR alarm_limit ...
VAR alarm ...
VAR beep_en ...
VAR key_count ...
VAR run ...
OK LIST_END
```

说明 STM32 能够在运行过程中枚举内部变量，并通过串口返回变量名称、类型、读写属性等信息。

### 4.4 GET / SET 测试

发送：

```text
GET temp_x10
```

可以读取当前模拟温度变量。

发送：

```text
SET alarm_limit 280
```

可以将报警阈值在线修改为 28.0℃。

再发送：

```text
GET alarm
```

当当前温度大于等于报警阈值时，返回：

```text
DATA alarm 1 bool
```

说明在线调参已经影响了系统运行状态。

## 5. 板端外设接入与调试

### 5.1 LED / BEEP / KEY 接入

在 no-LCD 最终演示版本中，接入了 LED、BEEP 和 KEY 驱动。最终确认的板端控制关系如下：

```text
PB5 = LED0，低电平点亮
PE5 = LED1，低电平点亮
PB8 = BEEP，高电平响
```

其中 LED0 可用于心跳或自检，LED1 可用于报警状态指示，BEEP 用于报警蜂鸣器反馈。KEY 驱动已接入，可作为本地调参或计数扩展。

### 5.2 BoardPort 自检

为了确认板级映射有效，在 `Board_Init()` 中加入板端自检流程：

```text
LED0 短亮
LED1 短亮
BEEP 短响
BOARD SELFTEST DONE
```

复位后 XCOM 能够看到 `BOARD SELFTEST DONE`，并且板端能够观察到 LED 与蜂鸣器动作，说明 BoardPort 到真实 GPIO 外设的链路已经打通。

### 5.3 报警反馈验证

当发送：

```text
SET alarm_limit 280
GET alarm
```

且 `GET alarm` 返回 `DATA alarm 1 bool` 后，板端 LED / BEEP 能产生报警反馈。发送：

```text
SET beep_en 0
```

后蜂鸣器关闭，但 `alarm` 报警状态不变，说明 PC 端可以在线控制蜂鸣器使能变量，并实时影响板端外设状态。

## 6. LCD 版本调试与取舍

项目过程中曾尝试加入 LCD 显示模块，用于显示温度、阈值、报警状态等信息。但加入 LCD、FSMC/SRAM 等相关驱动后，Keil 非商业版本出现代码大小限制错误：

```text
error: L6050U: The code size of this image exceeds the maximum allowed for this version of the linker.
```

为保证最终演示稳定可复现，最终采用 `atk_f103_nolcd.uvprojx` 对应的 no-LCD 瘦身版本。该版本保留 USART 在线变量监控、LED 报警、蜂鸣器报警、KEY 驱动接入等核心功能。LCD 接口在软件结构中保留为预留接口，但最终上板演示版本未启用 LCD 显示。

## 7. 最终演示版本

最终演示工程为：

```text
atk_f103_nolcd.uvprojx
```

最终演示命令顺序为：

```text
PING
LIST
GET temp_x10
SET alarm_limit 280
GET alarm
SET beep_en 0
```

该流程能够完整展示：

* PC 与 STM32 串口连通；
* STM32 返回运行时变量表；
* PC 读取运行时变量；
* PC 在线修改报警阈值；
* 修改参数后报警状态变化；
* LED 与蜂鸣器产生报警反馈；
* PC 在线关闭蜂鸣器使能。

## 8. 调试结论

本项目最终完成了题目要求的核心目标：在不使用 JTAG 调试器查看变量的情况下，通过 USART 串口和 PC 端简易界面实现 STM32 运行时变量读取与在线参数修改。实验结果表明，PC 端修改变量后能够实时影响 STM32 运行状态，并通过 LED 与蜂鸣器形成可观察的板端反馈。
