# 最终测试结果说明

本文件记录《基于 STM32F103ZE 的运行时变量监控与在线调参系统》最终 no-LCD 演示版本的测试结果。最终演示工程为：

```text
atk_f103_nolcd.uvprojx
```

PC 端使用 XCOM V2.8 作为串口调试界面，通过 CH340 USB 串口与 STM32F103ZE 开发板通信。

## 1. 测试环境

| 项目     | 内容                       |
| ------ | ------------------------ |
| 开发板    | 正点原子战舰 STM32F103ZE       |
| 最终固件工程 | `atk_f103_nolcd.uvprojx` |
| 编译环境   | Keil uVision5            |
| 下载方式   | ST-Link / JTAG           |
| PC 端工具 | XCOM V2.8                |
| 串口接口   | CH340 USB 串口             |
| 串口参数   | 115200, 8N1, None        |
| 协议格式   | ASCII 文本命令，勾选“发送新行”      |

## 2. 编译与下载结果

最终 no-LCD 工程在 Keil 中重新编译通过，编译结果为：

```text
0 Error(s), 0 Warning(s)
```

下载到开发板后，ST-Link 下载成功，程序能够正常运行。复位后 XCOM 能够收到启动信息：

```text
BOOT STM32_RUNTIME_MONITOR 1.0
HELP: LIST | GET <name> | SET <name> <value> | PING
```

说明固件已经成功烧录，并进入运行时变量监控系统。

## 3. 串口连通性测试

发送命令：

```text
PING
```

返回结果：

```text
OK PONG
```

测试结论：PC 端 XCOM 与 STM32 之间的串口通信链路正常，STM32 能够接收命令并返回应答。

## 4. 变量表枚举测试

发送命令：

```text
LIST
```

返回结果中包含多行变量信息，例如：

```text
VAR tick_s ...
VAR temp_x10 ...
VAR alarm_limit ...
VAR alarm ...
VAR beep_en ...
VAR key_count ...
VAR run ...
OK LIST_END
```

测试结论：STM32 能够在运行过程中返回内部变量表，说明变量注册和变量枚举功能正常。

## 5. 运行时变量读取测试

发送命令：

```text
GET temp_x10
```

返回结果示例：

```text
DATA temp_x10 312 0.1C
```

测试结论：PC 端可以在 STM32 程序运行过程中读取目标变量值。`temp_x10` 表示放大 10 倍的模拟温度，示例中 `312` 表示 31.2℃。

## 6. 在线参数修改测试

发送命令：

```text
SET alarm_limit 280
```

返回结果示例：

```text
OK SET alarm_limit 280
```

测试结论：PC 端可以在线修改 STM32 内部可写变量。此处将报警阈值设置为 28.0℃，不需要重新编译或重新下载程序。

## 7. 报警状态测试

发送命令：

```text
GET alarm
```

当当前模拟温度满足：

```text
temp_x10 >= alarm_limit
```

返回结果为：

```text
DATA alarm 1 bool
```

测试结论：修改报警阈值后，系统报警状态能够随运行时变量变化而更新，说明在线调参已经实时影响 STM32 程序运行状态。

## 8. LED 与蜂鸣器反馈测试

当 `alarm = 1` 且 `beep_en = 1` 时，板端能够产生报警反馈：

* LED 报警指示动作；
* 蜂鸣器响起。

发送命令：

```text
SET beep_en 0
```

返回结果示例：

```text
OK SET beep_en 0
```

此时蜂鸣器关闭，但 `alarm` 报警状态不变。

测试结论：PC 端不仅能读取和修改变量，还能通过修改变量实时影响板端 LED / BEEP 外设状态，验证了在线调参的实际效果。

## 9. 最终演示命令序列

最终视频演示按照以下命令顺序进行：

```text
PING
LIST
GET temp_x10
SET alarm_limit 280
GET alarm
SET beep_en 0
```

对应功能如下：

| 命令                    | 测试目的     | 测试结果                               |
| --------------------- | -------- | ---------------------------------- |
| `PING`                | 验证串口通信   | 返回 `OK PONG`                       |
| `LIST`                | 枚举变量表    | 返回多行 `VAR ...` 并以 `OK LIST_END` 结束 |
| `GET temp_x10`        | 读取模拟温度   | 返回当前温度变量                           |
| `SET alarm_limit 280` | 在线修改报警阈值 | 返回 `OK SET alarm_limit 280`        |
| `GET alarm`           | 读取报警状态   | 报警条件成立时返回 `DATA alarm 1 bool`      |
| `SET beep_en 0`       | 在线关闭蜂鸣器  | 蜂鸣器关闭，报警状态保持                       |

## 10. LCD 说明

项目开发过程中曾设计 LCD 显示接口，并尝试加入 LCD 相关驱动。但由于 Keil 非商业版本代码大小限制，加入 LCD 后工程体积超过限制。最终演示版本采用 no-LCD 瘦身版本，保留 USART 在线变量监控、LED 报警、蜂鸣器报警和 KEY 驱动接入等核心功能。

因此，最终测试结果不包含 LCD 显示效果，LCD 在本项目中作为预留接口说明。

## 11. 最终结论

最终 no-LCD 演示版本完成了以下目标：

* PC 端通过 XCOM 与 STM32 建立 USART 串口通信；
* STM32 能够返回运行时变量表；
* PC 端能够读取运行时变量；
* PC 端能够在线修改报警阈值等可写变量；
* 变量修改后能够实时影响报警状态；
* LED 与蜂鸣器能够产生板端反馈；
* PC 端能够通过 `SET beep_en 0` 在线关闭蜂鸣器。

实验结果表明，本系统实现了低成本的 STM32 运行时变量监控与在线调参功能，能够在目标程序持续运行的情况下完成变量读取、变量修改和外设状态反馈。
